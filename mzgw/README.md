# 秒针公文智能体 v2026 1.0

> 单文件、零安装的中文公文智能排版与校验工具，严格遵循 **GB/T 9704-2012《党政机关公文格式》**。

「秒针公文智能体」是一个纯前端（HTML + JavaScript）的公文写作助手：粘贴一段草稿，即可自动识别红头、文种、标题、主送机关、正文层级、附件与落款，实时渲染标准 A4 版式，并提供格式校验、一键修复与 Word/PDF 导出。整个应用只有一个 `index.html` 文件，双击即可在浏览器中运行。

## 📖 使用示例

### 示例 1：从草稿一键生成标准「通知」

**① 粘贴草稿**（含 Markdown 也无妨）：

```text
××省人民政府文件
×政发202611号
## **××省人民政府关于加快推进数字政府建设的通知**
各市、县人民政府，省政府各部门：
为深入贯彻落实党中央、国务院关于数字中国建设的决策部署，现将有关事项通知如下。
---
一、总体要求
坚持以人民为中心，统筹推进数字政府建设。
（一）基本原则
坚持党的全面领导，坚持整体协同。
二、主要任务
（一）夯实数字基础底座
加快建设一体化政务云平台。
三、保障措施
各地各部门要强化资金保障，确保任务落到实处。
附件：1.数字政府建设重点任务分工表
2.数字政府建设考核评估办法
××省人民政府
2026年8月4日
```

**② 点击「智能解析」** → 系统自动识别并填好：红头标志、发文字号（自动规范为 `×政发〔2026〕11号`）、标题、主送机关、正文（含一、二、三级标题）、附件说明、发文机关、成文日期。

**③ 右侧预览区立即呈现标准 A4 红头通知**；确认无误后点「**导出 Word（.docx）**」。

### 示例 3：制作上行文「请示」（自动要求签发人）

1. 文种选择「**请示**」（行文方向=上行文）。
2. 左侧自动出现「**签发人**」输入框——这是国标对上行文的强制要求。
3. 填写「签发人：张三」后，预览中发文字号居左空一字、签发人居右，与正文同处一行。
4. 点击「**智能校验**」→ 若遗漏签发人，会以「提醒」形式提示并支持一键修复。

---

### 示例 4：制作「函」（信函式格式）

1. 文种选择「**函**」。
2. 版式自动切换为**信函式**：发文机关标志下加武文线（红色上粗下细双线），发文字号居右顶格。
3. 填入商洽内容，导出后即为符合国标的平行文函件。

---

### 示例 5：粘贴带 Markdown 的草稿，一键净化

草稿中混有 `#`、`**`、`---`、`>`、`-` 等标记时，勾选「**净化符号**」再点「智能解析」，系统会：

- 去除 `#`、`*`、`>`、`-` 等 Markdown 记号；
- 将 `政发202611号`、`政发（2026）11号`、`政发<2026>11号` 统一规范为 `政发〔2026〕11号`；
- 统计并提示净化处数。

---

### 示例 6：批量导出多份公文为 ZIP

1. 制作好第 1 份公文后，点「**📦 批量导出**」→「**＋ 将当前公文加入批量队列**」。
2. 切换文种 / 改内容，重复加入队列（可设优先级）。
3. 点「**开始批量导出**」：支持后台运行（最小化弹窗继续）、断网自动暂停、恢复后断点续传。
4. 完成后获得 `批量公文_20260804.zip`，内含多份标准 `.docx`。

### 示例 7：导入已有文件继续编辑

- 支持 `.txt` / `.docx` / `.md` / `.markdown` 上传：拖拽或点击「**⇪ 上传文件**」即可读取文本（`.docx` 借助 mammoth 提取纯文本），随后照常「智能解析」。

## 🧪 公文要素与版式规范

| 要素 | 国标要求（GB/T 9704-2012） |
| --- | --- |
| 发文机关标志（红头） | 红色小标宋体，居中，上边缘至版心上边缘 35mm |
| 发文字号 | 三号仿宋；年份用六角括号「〔〕」，如 `×政发〔2026〕12号` |
| 标题 | 二号小标宋体，居中，可分两行 |
| 主送机关 | 三号仿宋，顶格，回行顶格 |
| 正文 | 三号方正仿宋_GBK，两端对齐；一级黑体 / 二级楷体 / 三级四级仿宋 |
| 附件说明 | 左空二字起排「附件：」，多附件序号悬挂对齐 |
| 发文机关署名 / 成文日期 | 居右；日期格式「×年×月×日」 |
| 抄送（版记） | 四号仿宋，置于末页版心底部，上、下各一条分隔线 |
| 页码 | Times New Roman，位于版心下边缘之下，居中 |

## ✅ 智能校验规则

校验模式分三档，**标准模式**已覆盖大多数场景：

| 模式 | 启用规则 |
| --- | --- |
| 宽松（loose） | 标题必填、正文必填、日期必填 |
| 标准（standard） | + 主送机关、署名、发文字号、附件配套 |
| 严格（strict） | + 上行文签发人、标题末尾无标点、标题≤50字、字号六角括号 |

内置规则（部分可一键修复）：

- `r_title` 标题必填（自动补全「关于××工作的<文种>」）
- `r_body` 正文必填
- `r_date` 成文日期必填且为「×年×月×日」
- `r_to` 主送机关必填
- `r_org` 发文机关署名必填
- `r_no` 红头文种发文字号必填
- `r_nofmt` 发文字号须用六角括号〔〕（自动修复）
- `r_attach` 附件内容须配套附件说明
- `r_sign` 上行文须标注签发人
- `r_titlepunct` 标题末尾不加标点（自动修复）
- `r_tplen` 标题超过 50 字建议精简

规则配置存于浏览器 `localStorage`，可通过「**☰ 规则库**」保存为团队预设，或「**⇪ 导出规则 / ⇱ 导入规则**」在设备间共享。

## 🛠 技术说明

- **运行环境**：纯静态单文件，无需安装、无需服务器、无需构建。
- **外部依赖**（通过公共 CDN 加载，首次运行需联网）：
  - [`docx@8.5.0`](https://cdn.jsdelivr.net/npm/docx@8.5.0) —— 生成 `.docx`
  - [`mammoth@1.6.0`](https://cdn.jsdelivr.net/npm/mammoth@1.6.0) —— 读取 `.docx` 文本
  - [`jszip@3.10.1`](https://cdn.jsdelivr.net/npm/jszip@3.10.1) —— 批量导出 ZIP
- **本地持久化**（浏览器 `localStorage`）：校验规则、批量队列、导出模板、导出历史。
- **离线能力**：核心排版、解析、校验、PDF 打印均不依赖网络；仅 Word 生成与 docx 读取需要前述 CDN 库。
- **字体依赖**：精确还原需安装方正公文系列字体（见「快速开始」提示）。

> 如需完全离线部署，可将三个 CDN 库下载到同目录并改写 `index.html` 顶部的 `<script src>` 为本地相对路径。

## ❓ 常见问题

**Q：打开后版式字体不对？**
A：本机未安装方正公文字体，已回退到系统仿宋/宋体/黑体/楷体。安装对应方正字体即可精确还原。

**Q：导出 Word 时提示失败？**
A：请确认网络可访问 CDN（docx.js）。或将三个依赖库改为本地引入实现完全离线。

**Q：PDF 导出空白 / 弹窗被拦截？**
A：允许浏览器弹出窗口后重试；PDF 通过打印窗口「另存为 PDF」，属浏览器原生能力，无需联网。

**Q：解析后附件/落款识别不全？**
A：保持「附件：」「附件1」「成文日期」等关键词规范；复杂稿件可在要素栏手动微调，所有改动实时反映到预览。
